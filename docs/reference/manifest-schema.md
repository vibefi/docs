---
title: Manifest Schema
---

The `manifest.json` file is the central metadata document for a VibeFi dapp bundle. It is generated by the CLI during the `package` command and verified by the Client before execution.

## Example Manifest

```json
{
  "name": "My Dapp",
  "version": "1.0.0",
  "description": "A decentralized frontend example",
  "createdAt": "2026-02-14T12:00:00.000Z",
  "constraints": {
    "type": "default",
    "allowedDependencies": {
      "react": "19.2.4",
      "react-dom": "19.2.4",
      "wagmi": "3.4.1",
      "viem": "2.45.0",
      "shadcn": "3.7.0",
      "@tanstack/react-query": "5.90.20"
    }
  },
  "entry": "index.html",
  "files": [
    {
      "path": "src/index.tsx",
      "bytes": 1234
    },
    {
      "path": "assets/logo.webp",
      "bytes": 5678
    }
  ]
}
```

## Field Definitions

### `name` (string)
The human-readable name of the dapp.

### `version` (string)
The version string of the dapp (e.g., `1.0.0`).

### `description` (string)
A brief summary of the dapp's purpose.

### `createdAt` (ISO8601 string)
The timestamp when the bundle was packaged.

### `constraints` (object)
Metadata about the security policy used during packaging.
- `type`: The constraint profile (default is `"default"`).
- `allowedDependencies`: A map of package names to their pinned versions.

### `entry` (string)
The main entry point for the dapp, usually `index.html`.

### `files` (array)
A list of all files included in the bundle.
- `path`: Relative path from the bundle root.
- `bytes`: The exact file size in bytes. The Client verifies these sizes against the actual files on disk.
